## Circle Inversion

Let's start with an introduction to geometric inversion. You're likely familiar with reflection across a line (line symmetry) and reflection through a point (point symmetry). There also exists **circle inversion** - an operation that exchanges the interior and exterior of a circle across the 2D plane.

### Mathematical Definition

For a circle with center O and radius r, inversion maps a point P to a point P' such that:

$$|OP| \cdot |OP'| = r^2$$

where OP and OP' point in the same direction.

Near the circle's circumference, the inside and outside exchange like a distorted line symmetry. Infinitely far points exchange with the circle's center.

### Inverting Lines

When inverting a line outside the circle:
- Points near the circle map to just inside the circumference
- Points far from the circle map closer to the center
- The result appears as a small circle inside the original circle

If we consider a straight line as a circle with infinite radius, then circle inversion exchanges circles inside and outside the boundary circle.

### Formula for Unit Circle Inversion

On the complex plane, inversion through the unit circle is expressed as:

$$z \rightarrow \frac{1}{\bar{z}}$$

where z is a complex number and z-bar is its complex conjugate.

Expanding this:

$$z \rightarrow \frac{1}{\bar{z}} = \frac{z}{|z|^2}$$

This shows that inversion scales z by the inverse of its squared magnitude.

### Complex Plane Operations

On the complex plane:
- **Addition** = Translation
- **Multiplication** = Rotation (and scaling)
- **Division** (including inversion) = A new type of transformation

---

## Mobius Transformations

Generalizing complex plane transformations to include division gives us the **Mobius transformation**:

$$z \rightarrow \frac{az + b}{cz + d}$$

where a, b, c, d are all complex numbers.

---

## Schottky Groups and Kleinian Groups

We can create fractal figures by repeatedly applying Mobius transformations.

### Construction

1. Prepare four non-intersecting circles: D_A, D_a, D_B, D_b
2. Create Mobius transformation **a** that maps the exterior of D_A to the interior of D_a (and vice versa)
3. Create Mobius transformation **b** that maps D_B exterior to D_b interior
4. Also define inverse transformations A and B

The set of all possible compositions of these four transformations (a, A, b, B) in any order (e.g., aaBAbbaB) is called a **Schottky group** generated by a and b.

**Kleinian groups** are the more general term for discrete groups of Mobius transformations.

---

## Limit Sets

Repeatedly applying Schottky group transformations produces circles within circles within circles, continuing infinitely. This infinite collection of nested circles is called the **limit set** of the Schottky group.

**Drawing this limit set is the goal of this chapter.**

---

## Jos Leys' Algorithm

### Overview

Naively implementing limit set rendering would be computationally infeasible due to infinite transformation combinations. Fortunately, Jos Leys has published an efficient algorithm for this purpose.

### The Transformations

We use two Mobius transformations:

$$a: z \rightarrow \frac{tz - i}{-iz}$$

$$b: z \rightarrow z + 2$$

where t is a complex number u + iv. Varying t changes the figure's shape.

### Analyzing Transformation a

Expanding transformation a:

$$a: z \rightarrow \frac{tz - i}{-iz} = \frac{1}{z} + (-v + iu)$$

Further:

$$\frac{1}{z} = \frac{x - iy}{|z|^2}$$

Therefore transformation a consists of:
1. Unit circle inversion
2. Negate the y-component (reflection)
3. Translate by (-v, u)

### The Limit Set Structure

The limit set forms a band-shaped figure of connected large and small circles with these properties:

- Bounded by 0 <= y <= u
- Horizontally repeating parallelograms between Line1 and Line2
- Line1 passes through (1, 0) and (1-v, u)
- Line2 passes through (-1, 0) and (-1-v, u)
- Line3 divides the figure, with upper and lower halves being point-symmetric about (-v/2, u/2)

### The Algorithm

To determine if a point belongs to the limit set:

1. If y < 0 or y > u, the point is **outside** the band
2. If right of Line1 or left of Line2, translate to center parallelogram
3. If above Line3, reflect through center point to below Line3
4. Apply transformation a
5. If y < 0 after transformation, the point is **in the limit set**
6. If the point equals the position from 2 iterations ago, it's **not in the limit set**
7. Otherwise, return to step 2

The key insight: applying transformation a to a point inside the largest circle (which touches y=0) results in y < 0. Therefore:

> If applying transformation a yields y < 0, the point is inside the largest circle, thus inside the limit set.

## Implementation

### C# Script

```csharp
private void OnRenderImage(RenderTexture source, RenderTexture destination)
{
    material.SetColor("_HitColor", hitColor);
    material.SetColor("_BackColor", backColor);
    material.SetInt("_Iteration", iteration);
    material.SetFloat("_Scale", scale);
    material.SetVector("_Offset", offset);
    material.SetVector("_Circle", circle);

    Vector2 uv = kleinUV;
    if (useUVAnimation)
    {
        uv = new Vector2(
            animKleinU.Evaluate(time),
            animKleinV.Evaluate(time)
        );
    }
    material.SetVector("_KleinUV", uv);
    Graphics.Blit(source, destination, material, pass);
}
```

### Fragment Shader

```hlsl
fixed4 frag (v2f_img i) : SV_Target
{
    float2 pos = i.uv;
    float aspect = _ScreenParams.x / _ScreenParams.y;
    pos.x *= aspect;
    pos += _Offset;
    pos *= _Scale;

    bool hit = josKleinian(pos, _KleinUV);
    return hit ? _HitColor : _BackColor;

```

### The josKleinian Function

```hlsl
bool josKleinian(float2 z, float2 t)
{
    float u = t.x;
    float v = t.y;

    float2 lz = z + (1).xx;    // Two iterations ago
    float2 llz = z + (-1).xx;  // One iteration ago

    for (uint i = 0; i < _Iteration; i++)
    {
        // Wrap to center parallelogram
        float offset_x = abs(v) / u * z.y;
        z.x += offset_x;
        z.x = wrap(z.x, 2, -1);
        z.x -= offset_x;

        // If above Line3, reflect through center point
        float separate_line = u * 0.5
            + sign(v) * (2 * u - 1.95) / 4 * sign(z.x + v * 0.5)
            * (1 - exp(-(7.2 - (1.95 - u) * 15) * abs(z.x + v * 0.5)));

        if (z.y >= separate_line)
        {
            z = float2(-v, u) - z;
        }

        // Apply transformation a
        z = TransA(z, t);

        // Hit detection
        if (z.y < 0) { return true; }

        // Two-cycle detection (not in limit set)
        if (length(z - llz) < 1e-6) { break; }

        llz = lz;
        lz = z;
    }

    return false;
}
```

### Transformation a Implementation

```hlsl
float2 TransA(float2 z, float2 t)
{
    // z -> (x - iy) / |z|^2 + (-v + iu)
    return float2(z.x, -z.y) / dot(z, z) + float2(-t.y, t.x);
}
```

### Wrap Function

```hlsl
float wrap(float x, float width, float left_side)
{
    x -= left_side;
    return (x - width * floor(x / width)) + left_side;
}
```

## Adding Circle Inversion for Animation

To create more interesting animations, we can apply an additional circle inversion before the limit set calculation:

```hlsl
float2 circleInverse(float2 pos, float2 center, float radius)
{
    float2 p = pos - center;
    p = (p * radius) / dot(p, p);
    p += center;
    return p;
}

fixed4 frag_circle_inverse(v2f_img i) : SV_Target
{
    float2 pos = i.uv;
    float aspect = _ScreenParams.x / _ScreenParams.y;
    pos.x *= aspect;
    pos *= _Scale;
    pos += _Offset;

    // Anti-aliasing through multi-sampling
    int sample_num = 10;
    float4 sum;
    for (int i = 0; i < sample_num; ++i)
    {
        float2 offset = rand2n(pos, i) * (1 / _ScreenParams.y) * 3;
        float2 p = circleInverse(pos + offset, _Circle.xy, _Circle.w);
        sum += calc_color(p);
    }

    return sum / sample_num;
}
```

Circle inversion:
- Exchanges the infinite exterior with the circle's interior
- Preserves circles as circles
- Creates unexpected, fascinating patterns when applied to the limit set

Moving the inversion circle or changing its radius produces mesmerizing fractal animations.

## Key Takeaways

1. **Circle inversion** exchanges interior/exterior regions, preserving circular shapes
2. **Mobius transformations** generalize complex plane operations including inversion
3. **Kleinian groups** generate fractal limit sets through repeated Mobius transformations
4. **Jos Leys' algorithm** efficiently determines limit set membership
5. **Two-cycle detection** identifies points outside the limit set
6. **Additional circle inversion** creates dramatic animation effects
